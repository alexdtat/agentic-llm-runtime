# Smoke Б1–Б5

Оформлено по одной простой задаче для первых пяти БАФ. Это smoke-режим из [README курса](../../reference/course/baf-source/README.md): одна простая задача на функцию, один повтор. Это не полный набор из трёх уровней сложности, не все восемь БАФ и не сравнение нескольких пар.

Б1 скопирован вместе с фикстурой и чекером из официального примера закреплённой ревизии курса. Б2–Б5 оформлены здесь по описаниям [официального каталога](../../reference/course/baf-source/catalog.yaml). Они не выдаются за скачанные официальные реализации. Источник курса находится в `reference/course/source.json` общего корня.

У каждой задачи есть `task.yaml`, `task.json`, `fixture/`, `check.py`. Новые `task.yaml` записаны в JSON-подмножестве YAML; runner читает `task.json`, поэтому YAML-библиотека ему не нужна. JSON Schema Б3 находится рядом с чекером, вне фикстуры.

## Прогон

Из общего корня `/home/alexdtat/Documents/Codex/2026-10-31/claude-x20/work/project-feasibility-2026-11-06`:

```bash
python3 baf_runner.py --checkers-only
python3 baf_runner.py
```

Для live-прогона HyperQwen должен уже работать. Runner не запускает и не останавливает сервер. Образ gateway собирается через compose из подготовленных исходников; образ CPU-сандбокса уже есть. Фиксированные условия записаны в [protocol-v1.json](protocol-v1.json) до модельного прогона: одна попытка на задачу, одна модель, тот же профиль, шесть шагов максимум, temperature 0, 256 выходных токенов, 180 секунд на задачу. Невалидные результаты не перегенерируются ради балла.

На каждую задачу создаётся новая сессия и чистый `/work`. Агент получает только содержимое `fixture/` и текст задачи; чекер, schema и эталоны остаются у оператора. После завершения отдельная программа получает снимок файлов и проверяет результат. Исходные файлы должны остаться неизменными, кроме явно редактируемого README в Б4. Б5 дополнительно требует реального вызова заданной команды по журналу инструментов.

## Что проверяется

| БАФ | Результат |
|---|---|
| Б1 | Порт сервиса в `answer.txt`; официальный чекер |
| Б2 | Путь к файлу определения `parse_date`, а не к месту импорта |
| Б3 | `config.json` по скрытой JSON Schema, с правильными типами и без лишних полей |
| Б4 | Только версия команды Install меняется; остальные байты README сохраняются |
| Б5 | Запуск `python3 stats.py data.csv`, правильная медиана в `answer.txt`, скрипт и данные не изменены |

Проверки чекеров включают правильные/неправильные ответы, глобальную замену версии вместо локальной, неверный JSON-тип, изменение входной фикстуры и попытку выдать ответ Б5 без запуска инструмента.

## Артефакты

Полный каталог `results/baf-suite-<timestamp>/` содержит снимок suite, протокол, исходники runner/harness, отдельные ответы модели, tool traces, снимок рабочей папки и решения чекеров. Одна строка на задачу сохраняется в `results/baf/hyperqwen-v0/<run>.jsonl` с полями `task_id`, `repeat`, `pass`, `reason`, `tokens_in`, `tokens_out`, `seconds`, `outcome`.

## Record/replay без модели

```bash
python3 baf_runner.py --replay-from results/baf-suite-20261106T015237658406Z
```

Это заново выполняет записанные действия через API в новых CPU-сандбоксах, заново собирает файлы и запускает чекеры. Модель не вызывается; её токены и вызовы записываются нулями, исходный live-прогон указан отдельно. При уже подготовленных Docker-образах и Python-зависимостях внешняя сеть не нужна. Replay проверяет программный pipeline и не является повторным замером качества модели.

Локальная модель применялась для технического smoke. Соответствие модели общим ограничениям курса для финального quality-бенчмарка здесь не установлено.
