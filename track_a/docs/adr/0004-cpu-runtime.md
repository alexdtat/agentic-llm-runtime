# ADR 0004: CPU runtime, gateway и private executor

Статус: реализовано; заменяет архитектурные допущения ADR 0001–0003 в части
хостового харнеса, отмены и неперсистентного состояния. Исторические ADR сохраняются.

## Решение

Два постоянно работающих сервиса Compose. Gateway объединяет HTTP frontend,
харнес и модельный адаптер; executor предоставляет фиксированный command API и
управляет Docker. SQLite отдельно у каждого владельца состояния. Тестовый runner,
CLI и build-only sandbox-image не являются дополнительными постоянными сервисами.
CPU Python slim и Docker CLI закреплены digest; никаких CUDA, GUI, SSHFS/FUSE в
исполняющем образе. Сеть сандбокса none. Model key только у gateway.

## Альтернативы и цена

- Оставить всё в gateway: меньше кода, но модельный парсер и публичный API получают
  Docker socket, cleanup не отделён от харнеса. Отвергнуто.
- Gateway + harness + broker + llm-proxy + очередь + БД-сервис: полезно для масштаба,
  но сейчас увеличивает число отказов/контрактов без нескольких пользователей и
  независимого масштабирования. Пока не нужно.
- Rootless Docker / отдельная ВМ / gVisor: сильнее ограничивают последствия
  компрометации executor, но требуют настройки хоста и самостоятельной проверки.
  Сейчас **не внедрены**; перенос socket не считается достаточным hardening.

SQLite snapshot прост и атомарен, но сериализует записи, растёт без TTL и не
поддерживает несколько реплик. Перед побочным действием сохраняется intent;
после crash активные операции завершаются interrupted, без повторного исполнения.
Контейнеры имеют scope label; startup executor очищает только свой scope.

## Отмена и процессы

Для одного общего временного workdir выбран один активный run. Cancel/timeout
закрывают всю сессию и удаляют контейнер; успешная отмена возможна только после
подтверждённого удаления. Это дороже и теряет tmpfs, зато не полагается на то,
что потомки останутся в process group. При обычном выходе worker использует
Linux subreaper и убирает потомков, включая setsid; он всё ещё разделяет UID с
командой и не является границей против враждебного кода.

`down -v` после штатной остановки убирает состояние. После SIGKILL сначала нужен
startup reconciliation, иначе динамические контейнеры остаются вне Compose.
Это ограничение явно описано и проверяется crash-тестом.

## Эксперименты

Обновление платформы не даёт права пересчитать метрики старого smoke. Исторический
харнес/протокол и результаты неизменны. Новый серверный харнес — отдельная
техническая версия; live оценка требует заранее согласованного нового протокола.
Mock/replay тестируют инфраструктуру. Вызов OpenAI-compatible endpoint —
настройка, а не подтверждённый прогон HyperQwen.
