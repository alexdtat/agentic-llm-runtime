# ADR 0001: HTTP polling для прототипа

Статус: решение только для технического прототипа; не финальная архитектура курса.

Для проверки сессий, команд, идемпотентности и отмены использован versioned HTTP API и опрос run state. Это позволяет проверить контракт независимо от UI и модели. Накопленные события возвращаются с run; единственный финальный result защищён от повторной отмены.

Альтернативы для финального клиента: SSE или WebSocket. Они пока не реализованы и не сравнивались. Текущий polling не является готовым потоком событий UI. Выбор транспорта нужно пересмотреть после определения десктоп-клиента и reconnect semantics.
