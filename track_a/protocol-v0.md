# Протокол v0 диагностического API

Все запросы, кроме health, требуют Bearer token. Session/run id генерирует сервер. Прототип публикуется только на loopback. Это исполняемый контракт командного транспорта; SSE, монтирование и полноценный десктопный клиент пока не интегрированы.

| Метод | Путь | Вход | Результат |
|---|---|---|---|
| GET | `/v0/health` | — | версия/готовность |
| POST | `/v0/sessions` | `request_id` | сессия и имя контейнера |
| POST | `/v0/sessions/{id}/runs` | `request_id`, `argv`, `timeout_seconds` | run id и состояние |
| GET | `/v0/runs/{id}` | — | состояние, накопленные events и финальный result |
| POST | `/v0/runs/{id}/cancel` | `{}` | запрос отмены, идемпотентно после завершения |
| DELETE | `/v0/sessions/{id}` | — | освобождение сессии и контейнера |

Повтор одного request_id с тем же содержимым возвращает прежний объект. Повтор run request_id с другим содержимым — HTTP 409. В run существует один финальный result, который не переписывается повторной отменой. `error_kind`: `command`, `timeout`, `cancelled`, `transport`, `sandbox`; stdout/stderr ограничены. Внутренняя ошибка Python-обвязки и сбой Docker пока не во всех случаях различаются точно.

Контейнер выполнения непривилегированный, без сети и capabilities, с readonly root и ограниченными tmpfs/CPU/RAM/PIDs. Это не доказательство полной изоляции. Gateway имеет Docker socket, что даёт широкие права на хосте; этот вариант только для локального прототипа, а его риски нужно разобрать в ADR. SSHFS из предыдущих проб не монтируется в эти контейнеры. В тестовом runtime нет ключей модели или пользовательских документов.
