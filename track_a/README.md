# A: рабочий транспортный прототип

Дополнительно готов [runner smoke-Б1–Б5](baf/README.md): [результаты](../BAF_RESULTS.md). Все пять простых задач прошли на локальной модели и в CPU record/replay.

Есть compose gateway, терминальный клиент, source-visible агентный цикл и непривилегированный CPU-сандбокс. Это подготовленная основа, а не полное выполнение A. Монтирование, GUI-клиент, SSE, полный БАФ-бенчмарк и полная политика изоляции пока не интегрированы.

## Ручная демонстрация клиента

Из корня репозитория, после задания `PROBE_TOKEN` в окружении:

```bash
DOCKER_BUILDKIT=0 COMPOSE_BAKE=false docker compose -f track_a/compose.yaml up -d --build
docker compose -f track_a/compose.yaml port gateway 8080
```

Compose собирает gateway и образ сандбокса из исходников. Порт публикуется на
loopback и выбирается автоматически. Задать `RUNTIME_URL=http://127.0.0.1:ПОРТ`
с полученным портом. Далее:

```bash
python3 -m track_a.cli health
python3 -m track_a.cli new
python3 -m track_a.cli exec SESSION_ID -- python3 -c 'print("hello from sandbox")'
python3 -m track_a.cli watch RUN_ID
python3 -m track_a.cli cancel RUN_ID
python3 -m track_a.cli close SESSION_ID
docker compose -f track_a/compose.yaml down
```

`SESSION_ID` и `RUN_ID` заменить значениями из предыдущих команд. `watch`
показывает события polling-запросами, это не SSE. Долгую команду можно отменить
из второго терминала. Закрытие сессии удаляет её временный workdir. Папка клиента
в этом варианте не монтируется. Пример переменной находится в `.env.example`.

Из корня общего прототипа:

```bash
python3 a_transport_smoke.py
```

Команда собирает gateway из исходников через compose, выбирает случайный локальный порт/токен, проверяет API и удаляет временные сервисы. Базовый образ `course-feasibility:2026-11-06` уже собран. Транспортный smoke не использует модель.

При уже работающем HyperQwen можно отдельно выполнить:

```bash
python3 a_agent_smoke.py
```

Это максимум шесть коротких модельных запросов на одной открытой задаче. Скрипт не запускает, не переключает и не останавливает HyperQwen. Агент читает файлы и делает правку через HTTP-протокол сандбокса; stdin, stdout/stderr и результат каждого инструмента сохраняются. Это техническая диагностика, не полный БАФ и не подтверждение соответствия модели ограничениям курса.

Контракт: [protocol-v0.md](protocol-v0.md), [JSON Schema](protocol-v0.schema.json). Команды runner выполняются только в `/work` отдельного контейнера без сети; host shell для команд агента не используется. Для API gateway всё ещё используется Docker socket — это осознанная широкая привилегия оператора прототипа и предмет будущего ADR, а не достигнутый production hardening.
