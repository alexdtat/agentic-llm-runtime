# Харнесы: исторический smoke и серверный CPU-v1

Собственная реализация разрешена A-4.1. Исторический `track_a/harness.py:run_agent`
и условия `track_a/baf/protocol-v1.json` сохранены. Его реальные результаты описаны
в `BAF_RESULTS.md`. Ни prompt, ни параметры выполненного эксперимента не менялись.
Новый серверный путь — отдельная техническая версия, без результатов live-оценки.

## Серверный цикл CPU-v1

`track_a/server.py:Gateway.execute`:

1. Собирает system-инструкцию `track_a/model.py:SYSTEM` и сообщение задачи.
2. Проверяет дедлайн, число шагов, общий размер контекста и состояние cancel.
3. Через `Model.ask` получает JSON-действие; пишет длительность, content и usage.
4. `finish` с текстовым answer завершает **цикл**, но не оценивает решение.
5. `exec` проверяется общим validator и отправляется private executor по HTTP v0.
6. Ожидает terminal run, добавляет stdout/stderr/exit code/error в контекст;
   публикует tool_result. Ошибка самой команды становится наблюдением модели.
7. Сбой инфраструктуры, формата/модели или бюджета завершает задачу ошибкой.

Ограничения этой версии: 8 шагов, 60 секунд, 128000 символов истории; команды
до 3 секунд, модельный HTTP до 20 секунд, максимум 512 output tokens.
Полного token budgeting, compaction и выбора реализации харнеса конфигурацией
ещё нет. Новая задача начинает новую историю даже в той же файловой сессии.

## Владение и проверка результата

`Gateway` хранит задачи/events в SQLite; `executor.State` хранит сессии и команды.
Задача эксклюзивно владеет сессией: сторонний exec получает 409. Команды харнеса
выполняются только через протокол, никогда через shell gateway или хоста.

`Model` — серверная граница API с ключом. Mock выполняет фиксированную
инфраструктурную последовательность, real backend — явно заданный совместимый
HTTP endpoint. Redirect и автоматические retries запрещены. Ответы исключений
не возвращаются клиенту целиком. У сандбокса нет доступа к API/ключу модели.

Правильность результата проверяется отдельно: `SessionTools` готовит фикстуры,
собирает snapshot и запускает `check_task` в доверенном runner. Checkers/schema
не попадают в `/work`. Коллектор ограничивает размер и отвергает symlink/special
nodes; он рассчитан на остановленные добросовестные инструменты, не на враждебный
процесс, подменяющий пути одновременно со сбором.

## Отмена, восстановление и наблюдаемость

Cancel удаляет сандбокс, подтверждает очистку, затем записывает terminal; поздний
ответ модели не запускает новый инструмент. У уже завершённой задачи result
не меняется. После рестарта незавершённые задачи получают interrupted; команды
не переисполняются. Сохранённый request_id возвращает прежний объект.

События started/model/tool_started/tool_result/result имеют последовательные
номера; клиент может переподключиться с последним sequence. SQLite хранит
сообщение, действия и наблюдения, usage и длительности вызовов модели.
Это не полный JSONL-трейс всех операций сессии и не SSE/stdout streaming.

[аудит](system-design-review.md).
