# Харнес первого прототипа

Собственная реализация разрешена A-4.1. Код: [run_agent](../track_a/harness.py).
Фиксированные условия выполненного smoke: [протокол](../track_a/baf/protocol-v1.json).

## Управляющий цикл

1. Сформировать system-инструкцию и пользовательскую задачу.
2. Проверить оставшийся временной бюджет и вызвать модель.
3. Сохранить сырой ответ и разобрать JSON-действие.
4. Для `exec` передать argv серверу через HTTP API сандбокса, дождаться result.
5. Добавить ответ модели и результат инструмента в историю следующего вызова.
6. Для `finish` сохранить ответ и остановить цикл.

Остановка также наступает при лимите шагов, истечении времени или необработанной
ошибке API/формата. Невалидный ответ не перегенерируется автоматически.
Утверждение модели о завершении не означает правильного решения: отдельный
БАФ-checker проверяет файлы и след инструментов после завершения агента.

## Разделение ответственности

- LLM предлагает следующее действие; она не исполняет команды сама.
- Харнес управляет вызовами, историей и ограничениями.
- Gateway проверяет транспортный контракт и управляет сессией.
- Worker внутри сандбокса запускает команду, ограничивает время и отменяет группу процессов.
- Доверенный runner готовит фикстуры, собирает снимок и вызывает скрытый checker.

Ключ модели остаётся на стороне оператора. В рабочую папку агента не передаются
check.py, скрытая schema и эталон. Команды не выполняются через host shell.

## Контекст и ошибки

Следующий запрос получает исходную постановку, предыдущие ответы модели и
JSON-результаты инструментов. Сжатие и персистентная память пока не реализованы.
Ошибка команды возвращается модели как наблюдение, после чего она может
выбрать другое действие. Ошибка сети или разбора JSON завершает текущую попытку
с сохранением промежуточных данных. Политики безопасных ретраев ещё предстоит
расширить; автоматически повторять неидемпотентную правку нельзя.

API различает command error, timeout, sandbox/transport failure и cancel.
`request_id` защищает повторный транспортный запрос от повторного исполнения
внутри текущего процесса сервера. Это не гарантия после рестарта gateway:
постоянное хранилище сессий пока отсутствует.
