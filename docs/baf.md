# Свой вариант БАФ для A‑9

Предложение для рассмотрения и утверждения студентом. Вариант включает восемь новых задач на функции курса, три задачи на дополнительную функцию и одну составную задачу. Задания расположены в [track_a/baf-v2/student](../track_a/baf-v2/student).

## Восемь функций курса

| ID | Что проверяется | Почему это одна функция агента |
|---|---|---|
| S-B1 | Извлечение подписанного окна отката Beacon из релизной записки | Нужное значение уже есть в заданном документе. Агент сопоставляет модуль и статус строки среди похожих чисел. |
| S-B2 | Поиск файла с точной директивой маршрутизации | Единственный результат — путь. Агент отличает действующую директиву от комментария, примера и имени с похожим префиксом. |
| S-B3 | Создание `profile.json` с заданными полями и типами | Готовые значения из формулировки нужно записать в новый объект. Ведущие нули должны сохраниться в строке, а флаг — иметь логический тип JSON. |
| S-B4 | Точечная правка таймера в TOML | Агент меняет один существующий параметр. Одинаковые числа в другой секции, значении строки и комментарии проверяют точность границ правки. |
| S-B5 | Выполнение команды измерителя и извлечение метрики из результата | Агент вызывает предписанный инструмент и отличает пиковую нагрузку от контрольных показателей. Выполнение подтверждается парой событий v2 `tool.started` и `tool.result` с одним идентификатором операции. |
| S-B6 | Реализация функции объединения диапазонов | Проверяется контракт функции при соприкосновении границ, пустых диапазонах, ошибочных границах и на входе, который требуется сохранить. |
| S-B7 | Выбор допустимого слота по нескольким ограничениям | Искомый слот получается применением правил длительности, завершения проверки и окна запрета к одному набору кандидатов. Важен допустимый контакт с границей запрета. |
| S-B8 | Сведение двух смен с дедупликацией отправок | Один итог строится из двух заранее заданных наборов записей. Повтор ID на стыке смен проверяет согласование источников перед суммированием. |

Файл ответа служит общим интерфейсом оценки. В каждой строке таблицы критерий проверяет решение агента при обработке содержимого или вызове инструмента. Фикстуры локальны и заданы полностью. Таймаут, проверка неизменности входов и изоляция исполнения обеспечивают условия оценки.

## Дополнительная функция N. Приведение текста к формальному стилю

Функция принимает готовое содержание и правило отображения. Результат оценивается по точному соблюдению правила представления, включая символы, пробелы и переводы строк. Критерий Б3 — наличие нового структурированного объекта с заданными полями и типами. Критерий Б4 — границы выбранной правки в уже существующем файле. В заданиях N правило применяется ко всему предложенному входу.

| ID | Правило | Почему это одна функция агента |
|---|---|---|
| S-N1 | Шаблон карточки, ASCII-регистр кода и буквальное сохранение остальных полей | Агент отображает готовые поля в заданный стиль. Случай с ведущими нулями проверяет сохранение исходного содержания. |
| S-N2 | Единый шаблон заголовка, внешние ёлочки и удвоение внутренних ASCII-кавычек | Агент применяет правило к каждой карточке в заданном порядке. Смешанные знаки в названии выявляют лишние замены. |
| S-N3 | Скобки, специальный маркер `NA` и экранирование литералов | Агент применяет одно правило записи токенов с приоритетом экранирования. Похожие токены, включая токен с двумя обратными чертами, проверяют точное выполнение правила. |

## Составная задача S-C1. Готовность отгрузки

| Шаг | Функция | Результат |
|---|---|---|
| 1 | Б2 | Найти действующий маршрут ровно для указанного комплекта. Среди кандидатов есть черновик нужного комплекта и действующий маршрут комплекта с похожим ID. |
| 2 | Б1 | Извлечь идентификатор, два пути и порог из выбранного маршрута. Порядок путей сохраняется в отчёте. |
| 3 | Б8 | Объединить записи двух журналов по `parcel_id`, посчитать уникальные грузы и сумму коробок. |
| 4 | Б7 | Сопоставить сумму с порогом. Сумма в фикстуре ровно достигает порога, поэтому сравнение должно включать равенство. |
| 5 | Б3 | Записать маршрут, пути, количества и статус в один JSON-файл с заданными типами. |

Каждый следующий шаг потребляет результат предыдущих. Путь указывает, откуда извлечь источники и порог. Из источников получается сумма, из суммы и порога — статус. Поля итогового JSON дают отдельные признаки ошибочного выбора маршрута, сведения или сравнения.

## Проверка

В рабочий каталог агента передаётся `fixture/`, сообщение берётся из `task.json`. Чекеры и эталоны находятся на стороне оценки. В S-B5 итоговый файл и требуемый вызов инструмента проверяются вместе. В S-B6 обычный файловый запуск чекера возвращает `infra_error`. Для проверки поведения функции нужен `check_isolated(workdir, run_python)` с доверенным изолированным исполнителем без сети и секретов.

Команда `python3 -m unittest -v test_baf_v2_student` проверяет вручную подготовленные правильные и ошибочные ответы. В тестах S-B5 используется фиксированный пример трейса v2. В тестах S-B6 выполняются только встроенные в тестовый файл примеры реализации. Эти проверки подтверждают поведение чекеров. Оценка качества пары «харнес + LLM» потребует полноценного прогона.
