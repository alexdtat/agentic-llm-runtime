# Smoke-БАФ через v2

Из корня репозитория запустите одну попытку на каждую из восьми простых задач курса.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m track_a.baf_smoke --output results/baf-smoke-ci
```

Workflow `CPU runtime` запускает эту команду и прикладывает её артефакты к `cpu-runtime-evidence`. Отдельный набор проверяет классификацию ошибок, свежесть фикстур и границы исполнения.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_baf_smoke
```

Каталог `track_a/baf-v2/smoke.json` выбирает исторические простые задачи Б1–Б5 и новые простые задачи Б6–Б8. Для каждой попытки стандартный v2 `Application` создаёт свежую сессию с копией её `fixture/`. Штатный последовательный харнес получает ответы от скриптового mock через валидатор `ModelProxy`, выполняет вызовы через `FixtureExecutor`, публикует события и возвращает снимок файлов после подтверждённой остановки. Внутрипроцессный транспорт использует v2 routes без сокетов.

| БАФ | Что проходит через диспетчер инструментов |
| --- | --- |
| Б1 | Чтение конфигурации, создание файла с извлечённым значением |
| Б2 | Перечисление файлов, чтение определения, запись пути |
| Б3 | Чтение спецификации, создание разбираемого JSON-объекта |
| Б4 | Чтение и перезапись нужного README с сохранением остальных файлов |
| Б5 | `RunCommand` с фиксированным аргументом, обработка результата, запись ответа |
| Б6 | Чтение спецификации, создание Python-файла с синтаксически корректным определением `slugify` |
| Б7 | Чтение расписания, запись результата |
| Б8 | Перечисление и чтение пяти CSV, запись результата |

Для Б5 точная команда `python3 stats.py data.csv` обрабатывается внутри fixture executor. Доверенный код читает CSV как данные и возвращает форму обычного ответа `RunCommand`. Исполнение shell, `stats.py` и кода из Б6 отсутствует. Б6 проверяется через AST. Файлы чекеров и данные скрытых проверок находятся вне provision payload. Границы mounted-исполнения проверяет отдельный набор тестов.

В `--output/<suite-id>/summary.json` находится сводка. Каждая строка указывает на `attempt.json` с ID сессии и запуска, исходом, результатом остановки и проверками. Рядом записываются доступные `events.json` и `files.json` с итоговыми байтами в base64. Коды выхода CLI: `0` для `pass`, `1` для `fail`, `2` для `infra_error`. Неверный артефакт или отсутствующие вызовы приводят к `fail`. Сбой инфраструктуры или неподтверждённая очистка приводят к `infra_error`.

Режим `synthetic_mock_fixture` подтверждает механику v2. Для формата A‑8 с дешёвой моделью или записью реальных ответов нужен отдельный прогон с соответствующим источником. Скрытые функциональные испытания Б6, оценка пары «харнес + LLM» и повторы полного БАФ-бенчмарка относятся к проверке качества.
## Полный живой mounted БАФ

На Linux desktop с уже запущенной локальной моделью и кешированными образами
Docker из checkout:

```bash
sudo -v && /usr/bin/python3 -B prototypes/mounted-runtime/live_baf_batch.py
```

По умолчанию проверяется `http://127.0.0.1:18020/v1/models`. Если каталог
возвращает несколько моделей, передайте `--model ID`. Для другого локального
порта используйте `--model-base http://127.0.0.1:PORT/v1`. Batch использует
`MODEL_API_KEY` при его наличии. Для порта 18020 он также умеет прочитать
уже настроенный локальный ключ HyperQwen. Ключ не включается в свидетельства.
Тот же интерпретатор должен импортировать PyYAML 6.0.3 в режиме `-I`.

Оставьте терминал открытым. Прогон проверяет и обновляет существующий sudo
timestamp без запроса пароля. Для каждого из 117 запусков создаётся свежий
синтетический RW-экспорт. Фикстуры, git revision, digest рабочего кода и модель
закрепляются в `results/baf-mounted-live/`. В B5.2 и B5.3 обе части задания
передаются в исходном порядке в одном запросе. `progress.json` показывает
результаты, а каталоги попыток содержат grade, трассу и итог очистки.

При ошибке модели в рамках протокола прогон записывает результат попытки и
продолжается. При ошибке провайдера, Docker или неподтверждённой очистке
прогон останавливается. Повтор той же команды пропускает подтверждённые
результаты и останавливается на незавершённой попытке, чтобы не повторить
запрос незаметно. `--output` позволяет явно начать отдельное измерение.
