# Первый чекпоинт: что показывает прототип

## Задача и демонстрация

Цель -- клиент-серверная среда, в которой агент работает с файлами пользователя
через удалённый сандбокс. Сейчас показаны сессия, исполнение команды, события,
отмена и освобождение ресурсов. Монтирование испытано отдельно; основной runtime
пока использует временный workdir без папки пользователя.

Короткая демонстрация: создать сессию терминальным клиентом, записать и прочитать
файл, запустить долгую команду и отменить её, закрыть сессию. Автоматическая
проверка этого пути -- `checkpoint_checks.py A --infrastructure`.

## Архитектура

Клиент → HTTP gateway → менеджер сессии → worker в Docker-сандбоксе.
Харнес вызывает модель отдельно; предложенный инструмент проходит через тот же
gateway. Модель выбирает действие, обычный код проверяет и исполняет его.
Выполнение команды с exit code 0 не тождественно правильному решению задачи.

Сессия владеет контейнером и временными файлами. Отмена создаёт сигнал для worker,
который завершает группу процессов команды. Закрытие удаляет контейнер.
Клиент получает события polling-запросами с номерами последовательности.
SSE, восстановление сессий после рестарта и desktop UI пока не сделаны.

## Почему такой прототип

HTTP/JSON упрощает независимую проверку контракта. Docker позволяет ограничить
процессы, память, файловую систему и сеть. Собственный небольшой харнес позволяет
проследить весь цикл без закрытого фреймворка; это прямо допускается A-4.1.
Цена решения -- необходимость самостоятельно расширять обработку ошибок,
персистентность и политики повторов.

У gateway есть Docker socket и широкие права оператора. Он не является доказанной
защитной границей. Команды агента работают в отдельном непривилегированном
контейнере без сети. Полный hardening ещё в работе.

## БАФ и результаты

БАФ проверяет способность пары «харнес + LLM» решить атомарную задачу с файлами.
Инфраструктурный тест проверяет протокол, отмену и изоляцию независимо от качества
модели. Подмена одного другим не позволяет диагностировать источник ошибки.

Б1 -- официальный пример; Б2–Б5 реализованы по каталогу. Есть фикстура, задача,
отдельная сессия, агентная трасса, снимок итоговых файлов и программный checker.
Все исходы сохранены. [Модельный smoke и replay](../BAF_RESULTS.md) разделены:
replay повторяет инструменты и проверяет цепочку, но не является новой попыткой LLM.

## Что проверять дальше

Интеграция клиентского монтирования, ограниченный SFTP-доступ и доверенный
mount-broker; обрыв связи и подтверждение сохранения; конфликты одновременной
правки; дополнительные тесты изоляции. Далее -- полный базис и сравнение пар.
SSHFS, NFS и собственный FUSE различаются сложностью развёртывания и контролем
семантики; окончательный выбор нужно оформить сравнением в ADR.
